# Контракт генерации и проверки черновика

Существующий `POST /api/generate`, его запрос и ответ не меняются. Для нового экрана используется отдельный `POST /api/draft`, поскольку существующий ответ объединяет проект и планы и не содержит источников для отдельных пунктов.

## Генерация

Запрос: `{ "answers": { "daily_tasks": "…", "current_project": "…", "next_six_months": "…", "tools_and_knowledge": "…" } }` — четыре подтверждённых непустых ответа, не более 4000 символов каждый; прочие поля отклоняются. Ответ: `{ "sections": [{ "topic": "daily_tasks", "items": [{ "text": "…", "source_topic": "daily_tasks", "evidence": "дословный фрагмент" }] }, …] }`: ровно четыре уникальные темы; каждый пункт содержит профессионально сформулированный текст и дословный непустой фрагмент соответствующего исходного ответа. Пустой список означает отсутствие сведений; лишних полей нет. Сервер валидирует схему, уникальность тем и буквальное наличие каждого фрагмента в ответе-источнике; неподтверждённые числа и собственные имена в тексте отклоняются эвристически. Модель получает инструкции исправлять речь и группировать только известные факты, без выдумывания должности, зарплаты, опыта, местоположения или условий. Дословное основание и эвристики не доказывают смысловую корректность перефразирования: черновик необходимо проверить человеку.

## Проверка

Отдельный `/api/completeness` принимает четыре **текущих раздела черновика** в поле `answers` (четыре строки, включая пустые). Возвращает четыре записи `{ topic, status, evidence, question }`; `status` — `sufficient / clarify / missing`; `evidence` — дословный фрагмент соответствующего раздела либо `null` при `missing`; `question` — нейтральный вопрос для каждой темы, включая `sufficient`. Нет общего балла. Проверка не переписывает текст. При редактировании черновика оценка помечается устаревшей и повторяется только по нажатию; скопировать как есть можно всегда, в том числе при сбоях или ожидании. Содержание можно редактировать по разделам; копирование возвращает обычный текст с заголовками и маркерами списков.

Оба новых маршрута используют серверную модель `gemini-3.5-flash-lite` с `store: false`, ограничениями размера, строгой схемой и безопасными ошибками. Никаких автоматических повторов, внешних источников или изменения ответов пользователя. После уточнения ответа пересоздание черновика возможно только по явному подтверждению; ошибка генерации не уничтожает существующие правки.

## План тестов

Только синтетические данные и заглушка модели: разговорные ответы → оформленные пункты (не дословная подстановка), разные темы и несколько фактов; пустые списки при отсутствии данных; отсутствие дополнительных условий; выдуманный фрагмент или явная новая цифра/имя отклоняются; ошибки модели, дубли тем, лишние поля, некорректные запросы; прежний `/api/generate` проходит неизменные тесты. Проверка — полные, расплывчатые и пустые разделы, вопросы и основания; редактирование, явная повторная проверка, отсутствие автоперезаписи, копирование во время загрузки и при ошибках, устаревшие ответы и 320/375/390 px. Модель и Production вживую не вызываются.

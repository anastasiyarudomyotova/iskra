# Контракт проверки полноты

`POST /api/completeness` принимает `{ "draft": "…" }` — текст единого редактируемого документа, до 16000 символов, включая пустую строку. Посторонние поля отклоняются, тело ограничено 64 КиБ. `/api/generate` не изменяется.

Ответ: `{ "assessment": [{ "topic": "daily_tasks", "status": "sufficient", "evidence": "дословный фрагмент", "question": "Что ещё стоит уточнить?" }, …] }`. Ровно по одной записи для тем `daily_tasks`, `current_project`, `next_six_months`, `tools_and_knowledge`, без дополнительных полей или общего балла. `status`: `sufficient`, `clarify`, `missing`. `evidence` — непустая дословная подстрока полного текста для `sufficient`/`clarify`, `null` для `missing`; `question` — нейтральный вопрос для каждой темы. Пустой текст допускает только `missing`.

Модель `gemini-3.5-flash-lite` получает документ как данные, не инструкции, и оценивает каждую тему по всему тексту. Сервер проверяет схему, уникальность тем, фрагменты и согласованность полей, а также эвристически отклоняет некоторые неподтверждённые числа, цитаты и имена в вопросах. Это не доказывает смысловую точность и отсутствие всех неподтверждённых предпосылок: результат остаётся советом для человека. Данные передаются провайдеру с `store: false`, без логирования содержимого.

Ошибки имеют формат `{ "error", "code", "retryable" }` без содержимого запроса, ответа модели или секретов. Результат относится к снимку текста; после правки текста оценка устаревает и повторяется только по кнопке. Оценка не меняет документ и не блокирует копирование. При ошибке или слишком длинном тексте сохраняются доступ к редактору и копирование.

Проверки выполняются только с синтетическими данными и заглушкой модели: смешанные статусы, пустой текст, ошибки провайдера, нарушение схемы, повтор тем, недословные основания и неподтверждённые детали. См. также `rich-draft-contract.md`.

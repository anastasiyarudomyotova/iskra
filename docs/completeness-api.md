# Контракт проверки полноты

Отдельный `POST /api/completeness`; существующий `/api/generate` не изменяется.
Проверка рекомендательная и не редактирует ответы или черновик.

## Запрос

`application/json`: `{ "answers": { "daily_tasks": "…", "current_project": "…", "next_six_months": "…", "tools_and_knowledge": "…" } }`. Все четыре ключа обязательны; значения — строки до 4000 символов, включая пустые. Посторонние поля отклоняются. Тело ограничено 64 КиБ.

## Успешный ответ

`{ "assessment": [{ "topic": "daily_tasks", "status": "sufficient", "evidence": "дословный фрагмент", "question": "Что ещё стоит уточнить?" }, …] }`. Ровно по одной записи для каждого из четырёх ключей, без дополнительных полей или общего балла. `status`: `sufficient`, `clarify`, `missing`. `evidence` — непустая дословная подстрока соответствующего раздела черновика для `sufficient`/`clarify`, `null` для `missing`. `question` — непустой нейтральный вопрос с вопросительным знаком для каждого статуса. Пустой или пробельный раздел допускает только `missing`. Фрагменты и согласованность полей валидируются на сервере; вопросы с неподтверждёнными числами, цитатами и словами с заглавной буквы вне начала предложения отклоняются эвристически; неверный результат отклоняется, а не исправляется догадкой.

Проверка смысловой достаточности производится моделью `gemini-3.5-flash-lite` по каждой теме, без оценки кандидата, должности или «правильности» вакансии. Разделы — данные, не инструкции; вопросы не должны содержать новых фактов или предпосылок. Дословная проверка фрагментов и эвристика вопросов не доказывают отсутствие всех неподтверждённых предпосылок или корректность семантической оценки, поэтому результат остаётся советом для человека. Данные передаются сервером провайдеру с `store: false`, без логирования содержимого.

## Ошибки и UI

Ошибки имеют существующий формат `{ "error", "code", "retryable" }`, без содержимого запроса, ответа модели или секретов. При сбое или недоступности проверки пользователь может повторить её или скопировать текущий черновик. Результат относится к снимку черновика на момент проверки; после редактирования черновика предыдущая оценка считается устаревшей. Замечания никогда не меняют текст. Пересборка черновика из изменённых ответов — только по явному подтверждению.

## Проверка

Только синтетические примеры: полные, расплывчатые и пустые ответы; ошибки провайдера; нарушение схемы, пропущенные или повторённые темы, недословный фрагмент, противоречивые поля. Проверяется также отсутствие в ответе лишних полей и добавленных фактов в черновике. Реальные персональные данные, записи и Production не используются.

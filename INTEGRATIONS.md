# Gemini / server API — «Искра»

## Статус и границы

На проверенном main доступны `POST /api/transcribe`, `POST /api/draft`,
`POST /api/completeness` и прежний `POST /api/generate`. Маршрута `/api/review`
нет: проверка текущего черновика реализована как `/api/completeness`; переименования
или алиаса нет. Флаг `NEXT_PUBLIC_ISKRA_MOCK=true` подменяет только расшифровку:
создание и проверка черновика по-прежнему вызывают сервер и Gemini.

- Провайдер: Gemini **Interactions API**, `POST https://generativelanguage.googleapis.com/v1beta/interactions`.
- Единственная разрешённая модель всех маршрутов: **`gemini-3.5-flash-lite`** (проверена авторами брифа на синтетических русском тексте и аудио).
- Каждый запрос: `store: false`, `background: false`, без `previous_interaction_id`, без streaming и инструментов.
- Ответ модели: `response_format` с JSON Schema; результат дополнительно проверяется Zod на сервере.
- Вызов выполняется только из серверного модуля с `server-only`. Ключ передаётся в заголовке `x-goog-api-key`, не в URL и не в браузерном bundle.
- В этой задаче живой API не вызывался: ключ не запрашивался и не использовался. Автоматические тесты перехватывают `fetch` и используют только синтетические данные.

`store: false` отключает сохранение истории Interactions для запроса, но **не отменяет условия обработки данных выбранного тарифа Gemini**. До реальных данных PM должен проверить условия аккаунта и согласие пользователя. Для приёмки использовать только вымышленные данные.

## Секреты окружения

| Переменная       | Обязательность                   | Поведение                                                                                                                 |
| ---------------- | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `GEMINI_API_KEY` | обязательна для реального режима | читается только на сервере; отсутствует/пуста → безопасный `503`, вызова провайдера нет                                   |
| `GEMINI_MODEL` | необязательна | Пустая или `gemini-3.5-flash-lite`; любое другое значение отклоняется безопасным 503. |
| `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN` | обязательны для live | Серверное соединение с Upstash; при отсутствии или сбое — 503 без Gemini. |
| `ISKRA_LIMITER_HMAC_KEY` | обязателен для live | Серверный случайный секрет не менее 32 символов для HMAC IP и операции. |

Локально значения задаются в `.env.local`, который не коммитится. На хостинге —
через серверные secrets/environment variables. Не использовать `NEXT_PUBLIC_` для
ключа, не вставлять ключ в команды, issue, PR или чат. После изменения env
перезапустить dev-сервер или сделать новый deployment.

## Контракт

Успешные ответы содержат ровно согласованные поля. Все четыре маршрута принимают только
`Content-Type: application/json` и возвращают `Cache-Control: no-store`.
Для `/api/draft`, `/api/completeness` и `/api/transcribe` обязателен заголовок
`Idempotency-Key` (16–128 ASCII букв, цифр, `_` или `-`); используйте новый
случайный ключ для каждого намеренного действия, а для его сетевого повтора —
тот же ключ. Повтор возвращает 409 без второго вызова Gemini; результат не хранится.
`/api/generate` для совместимости принимает запросы и без заголовка, но такие
повторы **не дедуплицируются**. Действуют общие лимиты и бюджет.

### `POST /api/transcribe`

```json
{ "audioBase64": "<canonical base64>", "mimeType": "audio/webm;codecs=opus" }
```

```json
{
  "transcript": "Вымышленный ответ.",
  "language": "Russian",
  "uncertainWords": []
}
```

Если речи нет, допустим успешный ответ с пустым `transcript`, `language: "Unknown"`
и пустым `uncertainWords`; UI попросит повторить запись или ввести текст. Это не
считается ошибкой модели и не должно превращаться в `502`.

Проверки до Gemini:

- строгий canonical base64 с padding; data URL, пробелы и повреждённая кодировка отклоняются;
- MIME нормализуется до базового audio-типа; разрешены WebM/Opus, OGG, MP4/M4A, MPEG/MP3, WAV, AAC, FLAC, AIFF и распространённые MIME-алиасы;
- фактический контейнер должен соответствовать MIME, содержать аудио и не содержать видео;
- WebM ограничена браузерным путём MediaRecorder: Opus; laced blocks отклоняются, чтобы не занизить длительность;
- декодированное аудио ≤ **3 MiB − 1024 байта**; JSON-запрос ≤ **4 MiB**;
- длительность ≤ **60 секунд** (+0,25 с на последний неполный аудиофрейм). Для WebM проверяются и заголовок, и максимальный cluster/block timestamp; короткое значение Duration не скрывает длинную запись;
- лимит тела проверяется при потоковом чтении, а не только по `Content-Length`.

Аудио и расшифровка существуют только в памяти обработки запроса. Приложение не
записывает их в файлы, БД, аналитику и серверные логи.

### `POST /api/generate`

```json
{
  "answers": {
    "daily_tasks": "Проверяет вымышленные отчёты.",
    "current_project": "Учебный каталог вымышленных товаров.",
    "next_six_months": "Продолжит учебный каталог.",
    "tools_and_knowledge": "Табличный редактор."
  }
}
```

```json
{
  "vacancy": {
    "position_title": "Не указано",
    "summary": "Работа с вымышленными отчётами.",
    "responsibilities": ["Проверять вымышленные отчёты"],
    "project_context": "Учебный каталог вымышленных товаров.",
    "tools_and_knowledge": ["Табличный редактор"],
    "missing_information": [
      "Название должности не указано",
      "Зарплата не указана"
    ],
    "vacancy_text": "Должность: не указано. Работа с вымышленными отчётами."
  }
}
```

Все четыре ответа обязательны, непустые после trim, каждый ≤ **4000 символов**;
JSON-запрос ≤ **64 KiB**. Дополнительные поля отклоняются. Значения сериализуются
как данные отдельно от системных правил. Промпт запрещает выдумывать должность,
зарплату, местоположение, график, уровень позиции и опыт; неизвестное должно
попадать в `missing_information`. Итог остаётся черновиком для проверки человеком.

### `POST /api/draft` — текущий UI

Запрос имеет тот же объект `answers` и ограничения, что `/api/generate` выше.
Ответ (пример с вымышленными данными):

```json
{
  "blocks": [{
    "heading": "Обязанности",
    "type": "bullet_list",
    "items": [{
      "text": "Проверять вымышленные отчёты.",
      "source_topic": "daily_tasks",
      "evidence": "Проверяет вымышленные отчёты."
    }]
  }]
}
```

Строгий объект: `blocks` содержит 1–30 блоков; `heading` — `null` или один из
«Обязанности», «О проекте», «Планы», «Знания и инструменты»; `type` —
`paragraph` или `bullet_list`; `items` — 1–30 пунктов (для абзаца ровно один).
Каждый пункт: `text` 1–1000 символов, `source_topic` — один из четырёх ключей
ответов, `evidence` — непустой дословный фрагмент соответствующего ответа до
4000 символов. Общая серверная оценка длины документа ограничена 16000 символами.
Нижние и верхние границы массивов применяются локально, а не отправляются в
схеме Gemini. Лишние поля, неподтверждённые фрагменты и некоторые неподтверждённые
имена и числа отклоняются. Это эвристики, не гарантия смысловой достоверности.

### `POST /api/completeness` — проверка текущего текста

Запрос `{ "draft": "текущий текст" }`; строка до 16000 символов, пустая строка
допустима, тело JSON до 64 KiB, другие поля отклоняются. Ответ:

```json
{"assessment":[
  {"topic":"daily_tasks","status":"missing","evidence":null,"question":"Какие задачи выполняются каждый день?"},
  {"topic":"current_project","status":"missing","evidence":null,"question":"Над каким проектом предстоит работать?"},
  {"topic":"next_six_months","status":"missing","evidence":null,"question":"Какие планы на полгода?"},
  {"topic":"tools_and_knowledge","status":"missing","evidence":null,"question":"Какие инструменты нужны?"}
]}
```

Ровно четыре уникальные темы, каждая со статусом `sufficient`, `clarify` или
`missing` и непустым вопросом до 500 символов, заканчивающимся `?`. `evidence`
для `missing` — `null`, иначе непустая дословная подстрока текста до 4000
символов; пустой текст допускает только `missing`. Сервер проверяет структуру,
цитаты и часть новых чисел/имён, но не гарантирует смысловую точность. Оценка —
совет, не изменяет документ и не блокирует копирование. Подробнее —
[docs/completeness-api.md](docs/completeness-api.md).

## Ошибки и повтор

Формат ошибки (дополняет контракт успешных ответов):

```json
{
  "error": "Понятное сообщение на русском.",
  "code": "RATE_LIMITED",
  "retryable": true
}
```

| HTTP  | Примеры                                                          | Поведение                                                   |
| ----- | ---------------------------------------------------------------- | ----------------------------------------------------------- |
| `400` | неверный JSON, пустой ответ, повреждённый base64                 | исправить вход; автоматически не повторять                  |
| `413` | превышен размер тела/аудио                                       | сократить запись/ответ                                      |
| `415` | неверный Content-Type или MIME                                   | использовать JSON / поддерживаемый audio-формат             |
| `422` | нечитаемый контейнер, слишком длинная запись                     | записать короче или ввести текст                            |
| `429` | квота Gemini                                                     | `Retry-After` ограничен 1–300 с; повторить позже            |
| `502` | невалидный JSON/схема модели, отказ провайдера обработать запрос | безопасная ошибка, можно повторить                          |
| `503` | нет ключа, сетевой сбой, HTTP 5xx провайдера                     | сохранить введённое, повторить позже или текстовый fallback |
| `504` | таймаут Gemini **30 с**                                          | повторить позже                                             |

Автоматических повторов на сервере нет: они увеличили бы расход квоты и задержку.
Существующий UI сохраняет ответы при ошибке и позволяет повторить действие.
Тела ошибок провайдера не читаются/не возвращаются; неизвестные исключения не
сериализуются. Для `/api/draft` при неуспешном HTTP-ответе Gemini приложение
записывает в серверный лог только числовой статус без тела или данных запроса. В Next.js отключены логирование входящих запросов, полных URL
fetch и пересылка браузерной консоли. Настройки access/body-логов самого хостинга
нужно проверить отдельно перед production.

## Проверка без ключа

```bash
npm ci
npm test          # Gemini endpoint mocked; реальный ключ не нужен
npm run verify    # hygiene + lint + typecheck + tests + production build
```

Тестовые PCM WAV и минимальный WebM генерируются в памяти. Бинарных записей в
репозитории нет. Покрыты контракт, лимиты, MIME/base64, длительность, отсутствие
ключа, 429/503, сеть, таймаут заголовков и тела ответа провайдера, malformed
output, schema validation, отсутствие утечек в ошибках/логах и передача ответов
как данных. Отдельные регрессии: laced/truncated WebM не принимается по короткому
заголовку Duration; проверяются поздние clusters и BlockGroup/BlockDuration;
невалидный UTF-8 в JSON отклоняется; автоматических повторов нет; корректный
no-speech ответ с пустым `transcript` принимается, а не даёт `502`.

## Runtime и совместимость

Проект использует Next.js 16.4 Cache Components. Этот режим требует стандартный
Node.js runtime и не поддерживает сегментный экспорт `runtime`, даже
`runtime = "nodejs"` (см. документацию установленной версии Next.js). Поэтому
маршруты используют обязательный Node.js runtime без устаревшего экспорта; сборка
показывает маршруты API как динамические (`ƒ`).

## Защита AI API и оставшиеся риски

После проверки входа все четыре маршрута используют один Upstash Lua EVAL:
скользящие 6 запросов/IP/60 с и 12 вызовов/24 ч глобально, 2 активных/IP,
3 глобально. Успешно зарезервированный вызов расходует дневную квоту даже при
ошибке. Для IP доверяется `x-vercel-forwarded-for` только при `VERCEL=1`;
отсутствующий или неподтверждённый IP отклоняется 503. Учитывайте общий NAT.

Lease действует 90 с и освобождается только после подтверждённого terminal status
провайдера. Сетевой сбой, HTTP-ошибка, таймаут или неполный ответ оставляют слот
до TTL; Gemini может продолжать работу и после него. Idempotency metadata живёт
24 ч; в Upstash передаются только HMAC IP, HMAC тела и operation key, путь,
случайный lease и счётчики, без текста, аудио или результата. Неподтверждённое
резервирование закрывает запрос 503; непонятный результат не повторяется сервером.
Upstash Free допускает сбой/потерю счётчиков при failover, поэтому это не строгий
денежный потолок; перед live нужен независимый провайдерский контроль расходов.
Тесты выполняют Lua в симуляторе Redis, не в реальном Upstash.

### WAF — только предложение, сейчас не настроено

В Vercel Firewall → Configure → New Rule: условие Method equals `POST` AND Path
starts with `/api/`; действие Rate Limit, Fixed Window, ключ IP, 20 запросов за
60 секунд, действие 429. Проверить существующие правила и staging, затем отдельно
согласовать публикацию: она меняет Production без деплоя. В `main` сейчас четыре
API-маршрута, все AI; будущие POST под `/api/` также попадут под правило.
Счётчики WAF региональные, не глобальный бюджет. Preview protection не отключать.
